# Loom feature guide

What each feature does, the Power Apps feature it matches, what to click, and one line to say.
Run `make sso && make run-sso`. Every user's password is `demo`.

| # | Feature | What it does | Power Apps equivalent | What to click | Say |
|---|---|---|---|---|---|
| 1 | Real SSO (OIDC) | Sign-in happens at the identity provider (Keycloak here). The app never sees a password. | Entra ID sign-in | `/login` → **Sign in with SSO** → `bob` / `demo` | "This is standard OpenID Connect. Pointing it at your Entra means changing three settings, not code." |
| 2 | Groups → roles | Roles come from the IdP's `groups` claim and sync at every sign-in. A change is audited. | Security roles assigned through Entra groups | Sign out, sign in as `alice`: the left menu shows only Refunds. Optional: Keycloak admin (`admin`/`admin`) → Users → alice → Groups → add `auditor`, sign in again, and Audit log appears | "Access is managed where you already manage people. Moving someone between groups changes what they can open." |
| 3 | App shell | Header with who you are, left menu filtered by role, the same layout in every tool | Model-driven app header and site map | Click between tools in the left menu | "One template change restyled every tool, including the two that fresh Devin sessions built." |
| 4 | Masking + audited reveal | Bank accounts, IDs and dates of birth are masked everywhere. Reveal needs a reason and is logged. | Column-level security | As `bob`, open a refund → **Reveal** → enter a reason | "Masking lives in one policy file, so every tool and every page gets it." |
| 5 | Audit log | Append-only (database triggers block edits and deletes), written in the same transaction as the change | Dataverse auditing | As `ivan`, open **Audit log**, filter by action `reveal` | "Who, when, what changed and why, for every tool, with no per-tool work." |
| 6 | Stage bar | The record's state machine, drawn as stages. Off-track states turn orange or red. | Business process flow | Open any refund or KYC case | "This bar is the same state machine the server enforces. You can't skip a stage by editing the URL." |
| 7 | Separation of duties | Requesters can't approve their own refunds; refunds over $1,000 need two different approvers | Approval flows in Power Automate | As `bob`, approve `TXN-10388` ($2,400): it shows 1 of 2. As `carol`, approve: Approved | "These are rules in code with named tests, not configuration someone can quietly change." |
| 8 | No double payment | The idempotency key is saved before calling the provider. A timeout becomes UNKNOWN, and reconcile settles it. Retries reuse the key. | No direct equivalent (custom connector plus custom logic) | As `bob` on an approved refund: set mode **timeout_after_accept** → **Execute payment** → Unknown (orange) → **Reconcile** → Paid | "This is where low-code building blocks run out, and it's your riskiest workflow." |
| 9 | Stale-write protection | Two people editing the same record: the second save is rejected, not silently overwritten | Not built in for canvas apps | Open a record in two tabs, act in one, then the other: "changed by someone else" | "No lost updates." |
| 10 | KYC queue (built by a fresh Devin session) | Claim, review, escalate, decide. Only the analyst who claimed a case can reveal its PII. | A model-driven queue app | As `dave`: claim a case, Reveal appears. As `heidi`: no Reveal | "A fresh session built this from one paragraph and inherited the controls without being told." |
| 11 | Feature flags (built by a fresh Devin session) | Engineers change staging; only release managers change production. Change history with rollback. | A custom app over an external API | As `frank`: no production controls. As `grace`: change production → **Roll back to this** | "Tool number two from the factory, also from one paragraph." |
| 12 | Fake data | Faker generates about 100 records across every status, created through the services so the rules and audit apply | Sample data | Scroll the refunds list | "Realistic volume, all fake identities." |
| 13 | Tests and CI | 94 tests, and every business rule has a named test. GitHub Actions runs them on every PR. | Test Engine (deprecated) | Show a green PR check or run `make test` | "Every rule you just saw is a test that runs before anything ships." |

**Be honest on camera:** Keycloak stands in for Entra. Roles sync at sign-in, not live. There's no SCIM, Conditional Access, DLP, monitoring or managed hosting, and the integrations are mocks (see Known gaps in the README).
